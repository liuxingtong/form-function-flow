# 基于分析结果的 Site 地块功能分区操作

## 目标

不是让数据直接替代设计，而是让数据先把 site 内部各地块的“真实使用压力、活动节律、功能错配和连接关系”讲清楚，再把这些证据翻译成功能分区。

## 一套可执行的操作框架

### 1. 先把地块分成“证据单元”

如果 `01_units.gpkg` 比设计地块更碎，先做两层结构：

- 分析单元：保留现有 `unit_id`
- 设计单元：把若干 `unit_id` 合并成真实可操作地块

做法是先分析细单元，再把结果汇总到设计地块，避免一开始分得太粗。

### 2. 为每个地块建立六组判断指标

每个设计地块都看六组证据：

1. 到发强度
   - arrivals、departures、od_in、od_out 的峰值和均值

2. 停留能力
   - stays、停留时长、连续活跃时长、夜间留存

3. 节律类型
   - 工作日偏强还是周末偏强
   - 白天型、夜间型、双峰型还是平稳型

4. 功能底盘
   - 现状 POI / AOI / 建筑用途 / 公服设施

5. 空间连接
   - 对站点、主路、慢行网络、边界阻隔的连接能力

6. 更新约束
   - 风貌保护、蓝绿空间、建设强度、交通承载、噪声与后勤条件

### 3. 先识别“地块角色”，再落功能

可以先把地块分成几类角色，再决定功能分区。

#### A. 交通转换核

特征：

- 到发强度高
- 峰值尖锐
- OD 通过性强
- 停留转化弱

适合功能：

- 综合换乘
- 快速到离站服务
- 高周转零售
- 导向型公共空间

不宜优先放：

- 低流动、长停留的大体量封闭功能

#### B. 高停留活力核

特征：

- 停留量高
- 晚间和周末仍活跃
- 餐饮、零售、文娱、公服混合度高

适合功能：

- 商业
- 文娱
- 展览
- 夜间活动
- 复合公共空间

操作重点：

- 做首层连续界面
- 提升慢行可达
- 用小地块和高渗透界面承接人流

#### C. 就业服务核

特征：

- 工作日白天流入强
- 夜间回落明显
- 办公、商务、交通服务占优

适合功能：

- 办公
- 商务服务
- 生产性服务
- 配套会议和展示

操作重点：

- 与站点步行 5 到 10 分钟圈叠合
- 配中午和晚高峰转换服务

#### D. 社区支撑核

特征：

- 夜间停留稳定
- 周边居住服务需求持续
- 高峰不一定最高，但全天较稳

适合功能：

- 社区商业
- 医疗
- 托育
- 养老
- 日常生活服务

操作重点：

- 避免被大客流主轴切碎
- 保持步行可达和安静界面

#### E. 后勤与低敏更新区

特征：

- 车行可达强
- 行人停留弱
- 阻隔高
- 风貌与界面活力要求低

适合功能：

- 配送
- 设备
- 停车整合
- 市政后勤
- 建设过渡期周转空间

操作重点：

- 把负外部性锁在可管理边缘
- 不占用最好的步行界面和核心活力面

#### F. 生态与开放空间修复区

特征：

- 蓝绿本底较好
- 结构性阻隔明显
- 适合承担疏解、渗透和缓冲功能

适合功能：

- 开放空间
- 慢行廊道
- 海绵设施
- 小型公共活动场地

操作重点：

- 不只做景观，要和通行组织、停留节点、周边首层业态联动

## 从分析走到分区的具体落地方法

### 方法一：阈值分组

适合先快速出概念方案。

做法：

- 用峰值到发、停留强度、工作日/周末差、距站距离、阻隔指数做 5 到 8 个指标
- 每个地块按高、中、低分档
- 按规则直接判别功能主导方向

优点是快，适合前期方案比较。

### 方法二：聚类后人工命名

适合 site 内部地块类型比较多时。

做法：

- 用真实原始时序提炼出的静态指标做聚类
- 再把每一类命名成“交通核 / 活力核 / 社区核 / 后勤区”等角色

优点是更容易发现直觉之外的组合类型。

### 方法三：功能适配矩阵

适合直接服务控规或城市设计。

给每个地块计算若干“适配分”：

- transit_score
- commerce_score
- office_score
- community_score
- logistics_score
- open_space_score

然后：

- 取最高分作为主导功能
- 取第二高分作为兼容功能
- 对低分功能设限制条件

这一步最容易和设计语言对接。

## 你现在就可以怎么做

如果要直接服务 site 内部功能分区，我建议按下面顺序推进：

1. 从真实时间戳数据生成 `unit_id x timestamp` 长表。
2. 按设计地块聚合成地块级原始指标。
3. 先做六类地块角色识别，不急着给具体业态面积。
4. 再把角色翻译成“主导功能 + 兼容功能 + 不宜功能”。
5. 最后才进入容积、界面、慢行、车行、开放空间和分期策略。

## 一个最实用的输出模板

建议你最终形成一张 `site_parcel_zoning_evidence.csv`，每行一个设计地块，至少包含：

- `parcel_id`
- `transit_score`
- `dwell_score`
- `weekday_bias`
- `weekend_bias`
- `night_activity_score`
- `connectivity_score`
- `constraint_score`
- `recommended_primary_function`
- `recommended_secondary_function`
- `functions_to_avoid`
- `design_action`

其中 `design_action` 可以直接写成设计指令，例如：

- “提高首层商业连续度”
- “保留后勤车行界面，减少主街开口”
- “布置夜间公共活动节点”
- “作为社区服务补足地块”
- “优先承接换乘与快速消费”
