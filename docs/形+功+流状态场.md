上海火车站城市状态识别与推演系统：四人分工与 Agent 执行文档（GMM 固定版）
方法意义
本方法将上海火车站周边 3km 范围内的城市空间划分为一组可计算的空间单元，并通过建筑形态、功能设施、交通运行、人口活动与空间阻隔等多源数据，识别每个单元在不同层面和不同时段下的城市状态。相比常规的单指标热力图或静态叠加分析，这套方法能够把分散的数据转化为具有城市机制含义的状态原型，例如断裂、承载、吸引、滞留、换乘压力、低效界面等，从而更清楚地揭示“空间为什么出现问题”以及“问题如何随时间和邻域关系发生变化”。因此，它不仅能指出哪里数值高、哪里数值低，还能判断不同空间单元在区域系统中的角色、矛盾和转化潜力。
识别一套动态状态对后续设计决策更有利。上海火车站周边的问题并不只发生在静态空间形态上，而是由日内人流变化、功能供给差异、南北阻隔、换乘压力和周边活动外溢共同形成。通过将形态、功能和运行三层状态组织为状态序列，并进一步统计状态转移关系，可以判断哪些区域长期处于高压状态，哪些区域只在早晚高峰或周末被激活，哪些区域具备从低效界面转化为站城服务节点的潜力。这样，基地内部改造就可以依据区域状态诊断结果，进一步判断哪里需要南北缝合，哪里需要换乘疏解，哪里适合功能植入，哪里应补充公共空间、慢行系统或弹性活动场地。
本项目固定采用 GMM（Gaussian Mixture Model，高斯混合模型） 作为三层状态识别和综合状态识别的核心方法。GMM 用于建立一套全区域共享的状态库，使所有空间单元都能在同一组状态原型中被识别、比较和排序；对于功能引力层和运行压力层，则进一步将四个代表性时段的识别结果排列成状态序列，并统计状态转移矩阵。该方法借鉴 State-sharing Hidden Markov Model 的共享状态思想，同时适应本项目以代表性时段和多源静态/准动态数据为主的数据条件。相比直接训练 HMM，采用“GMM 共享状态识别 + 状态序列重组 + 转移矩阵统计”的方式更稳健、解释性更强，也更适合四人小组在有限时间内完成并转译为设计判断。
方法论文背书：
Understanding Urban Dynamics via State-sharing Hidden Markov Model
Discovering Regions of Different Functions in a City Using Human Mobility and POIs
Revealing the core-periphery structure of cities
Contiguity-Based Spatial Weights

0.4 空间阻抗边表
02_edges.csv 是后续三层状态识别和第四人综合状态推演共同使用的空间关系底板。它不应简单使用“普通相邻 = 1.0、铁路阻隔 = 0.2”这样的人工权重，而应基于空间阻抗计算边权。
输出文件：
02_edges.csv（本仓库样例：`data/site_3km/02_edges.csv`，与 `01_units` 同脚本生成；`walk_*` 与部分 barrier 字段为 v1 启发式，见 `data/site_3km/04_feature_index.md`）
建议字段：
source_id
target_id
shared_length_m
centroid_dist_m
walk_dist_m
walk_time_min
cross_arterial
cross_rail
cross_river
cross_elevated
has_crossing_facility
crossing_type
barrier_cost
angular_cost
edge_cost
edge_conductance
edge_weight_norm
计算逻辑：
edge_cost = α * walk_time_min
          + λ1 * cross_arterial
          + λ2 * cross_rail
          + λ3 * cross_river
          + λ4 * cross_elevated
          - μ  * has_crossing_facility
          + γ * angular_cost
再将通行成本转化为传播能力：
edge_conductance = exp(-θ * edge_cost)
最后对每个 source_id 的所有边做行归一化：
edge_weight_norm = edge_conductance / sum(edge_conductance of source_id)
含义：
edge_weight_norm 表示两个空间单元之间城市状态传播的相对强度。它不是几何距离，而是由步行时间、阻隔成本、过街设施和空间连通性共同决定的“状态传播能力”。

**底板质量检查（推荐）**：运行 `scripts/visualize_units_edges_qa.py`，在 `data/site_3km/qa/` 查看 `units_ring_zones.png`（环带 + 站心）、`units_edges_touch_vs_bridge.png`（灰=相接、蓝=`proximity_bridge`、红=`knn_bridge`）、`edges_choropleth_conductance.png` 与 `edges_choropleth_edge_cost.png`（无向边按 `edge_conductance` / `edge_cost` 上色）、`degree_histogram.png`、`unit_area_histogram.png`、`qa_summary.json`；时序检查：`temporal_wd_we_curves.png`、`temporal_slice_mass_wd_we.png`、`temporal_flow_inflow_weight_weekday.png`，若存在地铁校准则另有 `temporal_metroflow_blend_mass_weekday.png`。

**启发式局限与对后续处理的影响 / 缓解**（与 `data/site_3km/04_feature_index.md` 一致）：
1. **仅地块相接（touch）会出现度为 0 的图斑或路缝两侧无共边**，图邻域传播（第四人）与依赖 `edge_weight_norm` 的加权邻域统计会断连或偏弱。缓解：`scripts/build_site_units_and_edges.py` 默认（a）对「无任何 touch 邻居」的单元增加 **`edge_kind=knn_bridge`** 最近邻弱边；（b）对质心距离在 **`proximity_radius_m`** 内且非 touch/knn 的对增加 **`proximity_bridge`**（贪心短边优先、每节点 **`proximity_max_per_node`** 上限），`edge_conductance` 分别乘以 `bridge_conductance_mult` / `proximity_conductance_mult`。下游可按 `edge_kind` 过滤或单独加权。若课题要求**严格只保留物理共享边界**，复算时加 `--no-proximity-bridges` 与/或 `--no-bridge-isolated`。
2. **`walk_dist_m` / `walk_time_min` 为质心直线×曲折系数**，非路网最短路径，运行层「真实可达时耗」会偏乐观或偏悲观。缓解：接入 OSM 步行网后用网络距离/时间替换并重算 `edge_cost` 与 `edge_weight_norm`；在仅做单元间**相对**阻抗排序的阶段可暂用 v1。
3. **屏障标志由质心连线与缓冲线/面相交判定**，与真实步行轨迹可能不一致（漏检/误检）。缓解：后续增加「共享边界 ∩ 缓冲铁路/快速路」的 OR 规则、补充过街设施与高架中心线层；叙事与政策判断时结合现场或高清影像校核。
5. **`parcel_touch` 与「被路网隔开」**：`parcel_touch` 表示**两地块多边形边界是否几何相接**，**不是**「能否过马路步行到达」。当道路用地（或未入地块库的空隙）位于两地块之间、且两侧地块边界不相接时，**没有 touch 边是几何定义下的合理结果**；它刻画的是「同一套地块划片下的贴邻关系」，而非城市步行连通度。若分析需要跨道路连通，应基于 **OSM 步行网** 另建「跨路」边表或用人行道中心线打断地块后再建邻接，并用网络距离/时间替换 `walk_*`；`knn_bridge` 仅补齐**在 touch 图中度为 0** 的斑块，不会为每一对「路两侧近邻」自动连边。

一、第一人：空间可供性状态识别
1. 做哪一层
空间可供性状态 / Spatial Affordance State
这一层描述城市空间的“慢变量”和物理底盘。它关注的不是简单的建筑密度高低，而是判断一个空间单元在物理上能否被穿越、停留、承载、改造或连接。
它回答的问题是：
这个空间单元在物理上允许什么？它是阻隔、渗透、承载、约束，还是潜在转化空间？
2. 输入什么
空间底板：
01_units.gpkg
02_edges.csv
主要数据：
01-建筑轮廓
05-DEM高程数据
06-建筑体块模型rhino
07-CAD
09-开源土地利用
11-蓝绿空间
14-城市建成区
风貌保护区范围
上海地块
上海道路

3. 固定方法：GMM 共享状态识别
本层不做时间序列，也不训练 HMM。固定采用 GMM 建立全区域共享的空间可供性状态库。
基本流程：
空间叠加 → 特征提取 → 标准化 → GMM 共享状态识别 → 状态概率输出 → 状态原型解释
4. 详细步骤
Step 1：空间叠加
以 unit_id 为基本单元，将建筑、道路、蓝绿、风貌、地形、土地利用和边表特征汇总到每个空间单元。
Step 2：构造空间可供性特征
对每个 unit_id 计算：
building_coverage          建筑覆盖率
building_density           建筑面积密度
avg_height                 平均高度
max_height                 最大高度
volume_intensity           体量强度
block_compactness          街坊紧凑度
building_fragmentation     建筑碎片度
road_density               道路密度
intersection_density       交叉口密度
green_blue_ratio           蓝绿空间占比
dem_mean                   平均高程
dem_slope                  高差/坡度
heritage_ratio             风貌保护区占比
landuse_mix                土地利用混合度
edge_conductance_mean      平均对外连通强度
edge_conductance_std       对外连通强度差异
barrier_index              阻隔指数
permeability_index         渗透性指数
其中：
barrier_index 可由 edge_cost、cross_rail、cross_arterial、cross_river、cross_elevated 综合得到。
permeability_index 可由 road_density、intersection_density、edge_weight_norm 综合得到。
Step 3：预处理
- 对偏态变量做 log(1+x)
- 对连续变量做 z-score 标准化
- 对缺失值做中位数填补，或用邻近单元均值填补
- 保留一份未标准化的解释性字段，用于后续状态解释
Step 4：训练 GMM 共享状态模型
将所有 unit_id 的形态观测向量放入同一个样本集，固定使用 GMM 训练共享状态模型。
推荐：
n_components = 6 或 7
covariance_type = full 或 diag
random_state 固定
模型输出：
morph_state
p_M1, p_M2, ..., p_MK
其中 morph_state 是概率最高的状态，p_Mk 是该单元属于第 k 类形态状态的概率。
Step 5：解释状态原型
根据每个 GMM component 的特征均值解释状态原型。不要直接使用 cluster_0 这类技术标签。
建议候选状态库（名称仅供参考，需要根据数据结果重新命名）：
M1 基础设施断裂带
M2 巨构封闭容器
M3 细颗粒渗透肌理
M4 垂直高强度锚点
M5 风貌慢更新肌理
M6 蓝绿开敞调节场
M7 低强度潜在转化边缘

3. 固定方法：GMM 综合状态识别 + 图邻域状态推演
本层也固定采用 GMM 识别综合城市状态。具体方法：
合并三层状态概率
→ 使用 GMM 识别综合状态

4. 详细步骤
Step 1：融合三层状态
对每个 unit_id × t_id 拼接：
[p_M1...p_MK, p_F1...p_FK, p_R1...p_RK]
再加入关键解释性驱动因子：
barrier_index
accessibility_index
poi_density
stay_proxy
green_blue_ratio
building_coverage
dist_to_station
edge_conductance_mean
Step 2：训练 GMM 综合状态模型
将所有 unit_id × t_id 的融合向量放在一起训练 GMM。
推荐：
n_components = 6 或 7
covariance_type = full 或 diag
random_state 固定
输出：
global_state
p_G1, p_G2, ..., p_GK
建议候选综合状态库：
G1 枢纽高压复合核
G2 断裂型高潜力缝合带
G3 站城激活前沿
G4 慢行生活保育区
G5 公共活动调节场
G6 低效残余过渡区
G7 高强度通勤节点
状态名称可根据实际 GMM component 的特征中心调整，但必须说明命名依据。
Step 3：构建综合状态转移矩阵
按 unit_id 恢复综合状态序列，并统计：
WD_AM → WD_PM
WD_PM → WD_EVE
WD_EVE → WE_PM
得到：
T_G[a,b] = P(global_state at t+1 = b | global_state at t = a)
Step 4：加入图邻域影响
根据 02_edges.csv 计算每个单元的邻居综合状态分布：
neighbor_G1_prob
neighbor_G2_prob
...
neighbor_GK_prob
计算方式：
neighbor_Gk_prob(i,t) = Σ edge_weight_norm(i,j) * p_Gk(j,t)
含义：某单元受到邻近空间状态影响的加权平均。
Step 5：设置设计情景变量
建议情景：
Scenario 0：现状延续
Scenario 1：南北连通增强
Scenario 2：公共服务与商业复合植入
Scenario 3：换乘压力疏解
每个情景转成外部变量：
connectivity_boost
program_boost
transfer_relief
public_space_boost
barrier_reduction
示例：
南北连通增强：barrier_reduction ↑, accessibility_index ↑, 跨铁路 edge_weight_norm ↑
公共服务与商业复合植入：poi_density ↑, public_service_density ↑, stay_attraction ↑
换乘压力疏解：congestion_proxy ↓, stay_pressure ↓, accessibility_index ↑
Step 6：计算情景下的下一轮状态概率
可采用可解释的状态更新逻辑：
next_state_score =
  current_transition_score
+ local_suitability_score
+ neighbor_state_influence
+ scenario_intervention_score
- barrier_penalty
再用 softmax 转为状态概率：
p_Gk_next = softmax(next_state_score_k)
Step 7：输出干预敏感性和优先级
计算：
intervention_sensitivity = p_target_state_after - p_target_state_before
优先级可以由以下因素综合：
priority_score = 问题状态概率
               + 转化潜力
               + 邻域传播收益
               + 与车站距离权重
               + 情景敏感性
